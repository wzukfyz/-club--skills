# Markdown 文档写作规范助手

基于 Google Markdown Style Guide（google.github.io/styleguide/docguide/style.html）提炼的写作与审查知识库，覆盖写作模板、21 条可机械判定的审查清单、中文排版适配，以及一份「常被误引的伪规则」清单。

## 适用场景

- 撰写、改写、审查 `.md` 文档：README、设计文档、API 文档、文档站页面、项目 Wiki；
- 询问 Markdown 排版细节：行宽、标题层级、列表缩进、代码块语言标识、引用式链接、表格取舍、HTML 用法；
- 粘贴一段 Markdown 要求「看看排版有没有问题」或「按规范改一下」；
- 涉及中文文档排版：中英文空格、全角标点、折行位置。

以下情况不要用：

- 代码文件内的注释、docstring / Javadoc / JSDoc 语法——那是代码注释规范的范围，这里只管独立文档；
- 需要 `.docx` 或 PDF 成品；
- 只问 Git 提交信息怎么写。

## 前置条件

- 规范分两份放在 `references/` 下：写作档与审查档，**一次只读一份**，不要预读；
- 路径用 `{baseDir}` 占位符表示技能根目录，系统会替换为实际路径；
- 写作档的 A–F 节给规则与模板，审查档的 G1–G21 是可独立使用的清单，H 节列出「常被误认为存在、实际并不存在」的规则。

## 步骤

### 1. 判定模式并读取对应文件

| 任务 | 读取 | 说明 |
|---|---|---|
| 快问（行宽多少？TODO 怎么标？） | 本文件的「速查」一节 | 零文件读取，直接答 |
| 写作、改写 | `{baseDir}/references/markdown.md` | A–F 节加反例表 |
| 审查、体检 | `{baseDir}/references/markdown-review.md` | G1–G21 清单加 H 防误引，可独立使用 |
| 写作后自查 | 先写作档，再审查档 | 两次读取，不要合并成一次 |

### 2. 执行

**写作模式**：套用写作档 C 节给出的文档骨架模板，产出可直接使用的 Markdown，含锚点与围栏语言标识。

**审查模式**：按 G1–G21 顺序逐条核对，输出「违规项 → 位置 → 规则出处（G 编号加写作档节号）→ 修正写法」。同一条规则的多处违规合并为一条，逐处列位置。

### 3. 标注出处

每条结论都要能指到写作档的具体节号。**非 Google 规则必须显式声明**——F 节的中文适配、D 节的处置建议都属于这一类，不能含糊地当成官方规定引用。H 节列出的「不存在规则」不得反向引用。

### 4. 速查（跨场景，可直接引用）

1. **行宽 80 字符**（按 code point，1 个汉字算 1），例外只有四类：链接、表格、标题、代码块；
2. **中文折行**落在 `。！？；` 之后，其次 `，、`，不在词中断行（非 Google 规则）；
3. **行尾不留空白**；需要硬换行时用行尾反斜杠，并尽量避免 `<br />`；
4. **标题只用 `#`**，`#` 后加空格、前后留空行；全文仅一个 H1，且与文件名近似；
5. **标题名唯一且完整**，子节标题带父级前缀；每个标题配锚点，防止深链断裂；
6. **有序列表用真实编号**（`1.` `2.` `3.`），懒人编号已废弃；嵌套统一 4 空格缩进；
7. **代码块一律用围栏并声明语言**；四空格缩进式代码块禁止使用；
8. **行内代码兼作转义**：伪路径、示例 URL、泛指的文件类型都用反引号包住；
9. **引用式链接**只在长链接、表格内、重复引用时使用，定义放在首次使用那一节的末尾；
10. **表格宁缺勿滥**：列多行少、单元格里塞长段落，一律改成列表；单元格内用引用式链接；
11. **TODO 没有官方规定**——被问到时明确说「本指南未规定」，不要把注释规范的格式搬过来。

## 异常处理

| 情况 | 处理方式 |
|---|---|
| 目标宿主不支持 `[TOC]` | 改用该宿主的目录方案，或手写锚点链接列表，不要照搬 Gitiles 指令 |
| 用户问 TODO 格式 | 答「本指南无规定」，可给非官方建议但须标注清楚 |
| 用户问中文排版 | 走 F 节，每条都说明这是「非 Google 规则」 |
| 用户项目已有自有规范 | 项目规范优先，本技能只作补充参考 |
| 文档需要 Word 或 PDF 成品 | 转交对应的文档生成工具，本技能只负责 `.md` 内容 |
| 代码块里要嵌套代码块 | 外层改用四反引号或波浪线围栏，避免提前闭合 |
| 拿不准原文是否规定过 | 先查 H 节；H 节没有记载就回答「未核实」，不要臆造 |

## 验收标准

- [ ] 写作模式的产出物本身符合本规范（自指），交付前按 G1–G21 自检过一遍；
- [ ] 审查模式按 G1–G21 顺序输出，同规则多处违规已合并，每处都标了位置；
- [ ] 全部通过时给出「G1–G21 全部通过」，并附行宽与锚点覆盖率的实测数字；
- [ ] 每条结论都有规则出处，H 节列出的伪规则没有被反向引用；
- [ ] 涉及宿主差异（`[TOC]`、脚注、raw HTML）时，先确认渲染器再给方案；
- [ ] 明确超出范围时（代码注释、`.docx` 成品、提交信息）已转交或说明。

# 需求澄清助手

在动手之前用结构化提问澄清模糊需求。它不扮演任何角色，只作为需求分析的前置环节，确保后续工作建立在明确的信息上。

**核心原则：宁可多问一句，不可盲目执行。**

## 适用场景

请求出现以下模糊信号时使用。

### 目标模糊

- 「帮我分析一下」「帮我看看」「帮我检查一下」
- 「看看这个数据」「处理一下这个文件」
- 「做个图表」「画个图」「可视化」
- 「优化一下」「改进一下」「重构一下」
- 「改一下这个」「修复一下」
- 「帮我写个脚本」「帮我写个程序」「实现一个功能」
- 「生成报告」「做个总结」「整理一下」

### 指标或维度缺失

- 「分析销售数据」——按产品？按地区？还是按时间？
- 「用户画像」——哪些维度？什么粒度？
- 「性能优化」——哪个指标？目标值多少？
- 「做个对比」——和什么比？按什么标准？

### 数据或上下文不足

- 未说明数据来源（数据库 / CSV / API / 手动输入）
- 未说明文件路径或字段含义
- 未说明时间范围（「最近的」是多近）
- 引用了对话中不存在的文件或变量

### 输出偏好不明

- 未指定交付形式（代码 / 图表 / 文档 / PPT / 仪表板）
- 未指定文件格式（PNG / HTML / PDF / Markdown）
- 未指定技术栈偏好

### 风格约束未提

- 图表：配色、分辨率、交互要求
- 代码：语言、框架、注释风格
- 文档：详细程度、受众、模板

### 多义性请求

- 「做一个像 xxx 一样的东西」——哪些特性要模仿？
- 「简单处理一下」——「简单」的标准是什么？
- 「尽快」——有没有硬性截止时间？

**以下情况不要用：** 请求已包含清晰完整的需求描述，直接放行。

- 「请生成 2023 年 A 产品月销售额的折线图，保存为 PNG」——直接执行
- 「用 Python 读取 data.csv，按 city 列分组求 sale 列的均值，结果保存为 JSON」——直接执行

## 前置条件

- 纯对话型技能，无脚本、无外部依赖；
- 激活后必须**暂停一切实质性工作**（写代码、处理数据、生成文件），等用户回答再继续。

## 步骤

### 1. 判断是否触发

逐条比对上面列出的模糊信号。命中任一即触发；请求已足够明确则直接放行，不要拦下来问一遍。

### 2. 设计问卷

按四条原则裁剪问题：

1. **逻辑分组**——按「业务目标 → 数据理解 → 技术偏好 → 输出要求」组织；
2. **选项化优先**——常见选择给出候选（图表类型、时间粒度、文件格式），降低用户回答成本；
3. **开放问题辅助**——保留 1~2 个开放问题，挖掘深层业务背景；
4. **按需裁剪**——不是每次都问全套，只问缺失的关键信息。

### 3. 输出问卷

按下面模板输出。措辞可按语境微调，不相关的分组整组删掉。

---

📋 **需求澄清问卷**

您好！为了更精准地满足您的需求，我需要先了解以下几个方面的信息。请您逐一回答（可直接标号回复）。

#### 1️⃣ 业务目标

- **核心问题**：您希望通过本次分析或输出，回答什么业务问题、达成什么目的？
- **决策场景**：这份成果用于（周报展示 / 内部决策 / 对外发布 / 个人学习）？

#### 2️⃣ 数据与字段

- **数据来源**：来自数据库、本地文件（CSV / Excel）还是 API？请提供样本或字段说明。
- **关键维度**：最关心的维度或字段是哪些？（例如时间、地区、产品类别）
- **度量指标**：需要计算哪些指标？（如销售额、转化率、平均值）
- **时间范围**：分析周期是？（如近 3 个月、特定年份、环比或同比）

#### 3️⃣ 技术偏好

- **图表或输出类型**：更倾向哪种形式？（静态图表 / 交互式可视化 / 表格 / 文字报告）
- **工具栈**：有偏好的技术吗？（如 Python + Plotly、ECharts、Tableau、Excel）
- **风格要求**：配色（商务蓝 / 暖色 / 自定义）、字体、分辨率等特殊要求。

#### 4️⃣ 交付物与格式

- **交付形式**：希望收到什么？（仅代码 / 代码加图片 / 完整文档 / 可部署仪表板）
- **存储路径**：有指定的保存目录吗？如有请给绝对路径。
- **附加需求**：是否需要数据清洗、异常值处理或结论建议？

---

请根据以上问题逐项回复。收到明确回答后，我将立即执行任务。

### 4. 等待并复述答复

暂停执行，等用户回答。收到后把关键信息以结构化形式复述一遍请用户确认，避免理解偏差。

### 5. 移交或执行

信息完整后进入实际任务，或转交合适的后续环节。给用户一句明确交代：「需求已明确，现在开始……」

## 异常处理

| 情况 | 处理方式 |
|---|---|
| 首次回答仍不充分 | 基于回答补充追问，例如用户选了「交互图表」，再问「是否需要悬停提示」 |
| 用户说「你决定」 | 给出 2~3 个具体方案让用户选，不要替用户拍板后直接执行 |
| 用户标「未知」或「待定」 | 记为假设，并在复述时显式列出，说明该假设会影响哪些结果 |
| 用户明显着急 | 只问最关键的 1~2 个问题，其余按合理默认推进并声明所用默认值 |

## 验收标准

- [ ] 触发判断有依据，没有把需求明确的请求也拦下来问一遍；
- [ ] 问卷按四个维度分组，不相关的分组已删除；
- [ ] 常见选项已给出候选，而不是全部开放式提问；
- [ ] 得到答复后做了结构化复述，并经用户确认；
- [ ] 结束时明确交代了下一步动作。
